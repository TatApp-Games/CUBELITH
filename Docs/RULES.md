## 2. コアゲームループ

1. **難易度設定**: プレイヤーが「空間サイズ N」と「分割数 M」を選ぶ
2. **自動生成**: 条件に基づき、バラバラのクリスタルピースが空中に散らばった状態で生成される
3. **パズルプレイ**: ピースをドラッグ / スワイプで移動・回転し、N × N × N の立方体に組み上げる
4. **クリア演出**: 完全な立方体が完成すると、発光と融合の演出とともに 1 つの巨大クリスタルになる
5. クリア画面から「もう一度（同じ条件で再生成）」「難易度を変える」に戻れる

## 3. ゲームシステム

### 3.1 難易度・パラメータ

- **空間サイズ N**: 3〜7（整数）。既定 3
- **ピース分割数 M**: N ごとに次の 5 段のプリセットから選ぶ（N から N−2 刻み。最大は N + 4(N−2)）。既定は N=3 / M=4

  | N | M の選択肢 |
  |---|---|
  | 3 | 3 / 4 / 5 / 6 / 7 |
  | 4 | 4 / 6 / 8 / 10 / 12 |
  | 5 | 5 / 8 / 11 / 14 / 17 |
  | 6 | 6 / 10 / 14 / 18 / 22 |
  | 7 | 7 / 12 / 17 / 22 / 27 |
- **乱数シード**: 生成の再現用に数値シード（符号なし 32 bit）を持つ。UI には出さなくてよいが、検証のために外から指定できるようにする（指定の方法は各実装仕様）

### 3.2 プロシージャル生成（領域拡張 / Region Growing）

1. N × N × N の 3 次元配列（各セル = ボクセル）を用意し、すべて未割り当てにする
2. ランダムな相異なる座標に M 個のシード（核）を置き、それぞれをピース id 0..M-1 に割り当てる
3. 各ピースが、自分のボクセルに隣接（6 近傍）する未割り当てボクセルを 1 つ吸収する、をラウンドロビンで繰り返す。空間全体が埋まるまで続ける
   - あるピースの周囲に空きが無ければそのラウンドはスキップ
   - すべてのピースがスキップになったのに空きが残る場合（孤立した空き）は、残りを隣接するいずれかのピースに吸収させる
4. 結果として各ピースは**連結**したボクセル集合になる（連結性はテストで保証する）
5. 各ピースのボクセル座標は「解答位置」として保持し、プレイ開始時にランダムな位置・向き（90 度単位の 24 通りのいずれか）で空中に散らす。散らす範囲は立方体の周囲（各軸 ±(N+2) 程度）で、ピース同士が重ならないようにする

### 3.3 操作システム

- **ピース選択**: クリック / タップでピースをアクティブ化。アクティブなピースは縁取りかハイライトで示す。何も無い場所を押しても選択は外れない（外れるのは「散らし直す」などの操作だけ）
- **移動**: アクティブなピースをドラッグ / スワイプで、**グリッド（ボクセル単位）に沿って** X / Y / Z 軸方向に移動する
  - ドラッグは画面平面上の移動をカメラの向きに応じて 2 軸に写像する。奥行き方向の専用操作は持たない。カメラを回してその軸を画面上に出してからドラッグする
  - 移動はボクセル単位で確定し、中間位置ではスナップ候補（3.5）を計算する
- **回転**: 2 本指スワイプ / ひねり、回転モードのドラッグ、または回転ギズモで、アクティブなピースを **90 度単位**で回転する。回転はピースの局所原点（最初のボクセル、または重心に最も近いボクセル）を中心に行う
- **カメラ**: ピース以外の場所から始めたドラッグはカメラの旋回（注視点まわりの軌道カメラ。ピースを選択中でも旋回し、選択は保つ）。ホイール / ピンチでズーム（ピースの選択の有無によらない）
- **やり直し**: 「散らし直す（同じ配置に戻す）」ボタンを HUD に置く

### 3.4 クリア判定

- 全ピースを「グリッド座標 + 24 通りの向き」で表し、各ピースのボクセルをワールドのグリッド座標に変換する
- 変換後のボクセル集合が、**N × N × N のいずれかの位置**（原点は問わない。ピース群が作る立方体がどこにあってもよい）に重複なく・はみ出しなく収まればクリア
- 物理判定は使わない。配列のインデックス計算のみで行う。判定はピースを動かすたびに実行する

### 3.5 マグネット・スナップ

- プレイヤーが手を離したとき、アクティブなピースが「正解に近い位置」（既に置かれている他のピースと隣接して整合し、かつ重ならない位置が **半マス〜1 マス以内**にある）なら、その位置へ自動で吸い付く
- 「正解に近い」の定義（初版）: 他のピースと少なくとも 1 面で接し、重なりが無く、全ピースの外接立方体が N × N × N に収まる位置。候補が複数あれば最も近いもの
- 補間: 現在位置からスナップ先へ 100〜150 ms で滑らかに移動（lerp / easing）
- 効果音: 吸い付いた瞬間にガラスが組み合う短い SE を鳴らす

### 3.6 乱数と再現性

- 乱数はシード付きの mulberry32 を使う。生成（3.2）と初期散らし（3.2-5）はこの乱数だけで決める
- 同じ条件（N・M ほか難易度の選択）とシードなら、生成と初期散らしの結果を **Web 版と UE 版で完全に一致させる**
- 乱数の消費順など文章では決めきれない細部は **`WebMock/src/core` の実装を正**とする。UE 版は WebMock から書き出した照合データ（golden fixtures）との一致をテストで確かめる
- 生成や散らしの結果が変わるルール変更は、変更履歴の「生成への影響」に書く（UE 版の照合データを作り直す合図になる）

## 5. 演出

### 5.1 マグネット・スナップ演出

3.5 のとおり。加えて、スナップ候補がある間はピースを薄く光らせる（プレイヤーに「手を離せば吸い付く」ことを伝える）。

### 5.2 完成時のカタルシス：巨大クリスタルへの融合

クリア判定が真になった瞬間、次を **この順序で** 2〜3 秒かけて再生する。

1. **発光**: 全ボクセルの内部コアの発光強度が連動して最大まで上がり、画面全体が明るくなる
2. **融合**: ピースの境界（エッジ / 縁取り）がフェードアウトし、1 つの N × N × N の立方体に差し替わる
3. **パーティクル**: 立方体の中心から光の粒子（数百〜千粒）が放射状に広がる
4. **カメラ**: カメラが立方体の周囲を自動でゆっくり旋回する（操作は無効化。クリア画面の「もう一度」で解除）

## 6. UI

- **タイトル / 難易度選択画面**: N（3〜7）と M のプリセットを選んで「開始」。シードの表示（小さく）
- **プレイ中 HUD**: 回転モードのトグル（「回転 / 回転解除」）、「固定 / 固定解除」、「散らし直す」、「難易度へ戻る」、「ヒント」、「次の問題」、残りピース数（未確定のピース数）
- **固定の表示**: 固定中のピースは各ボクセルの中心に南京錠アイコンを出す（銀 = 手動の固定、金 = ヒントで置いたもの）。そのピースの内部発光コアは消す（クリア演出の発光では他のボクセルと一緒に光る）
- **クリア画面**: 「もう一度」「難易度を変える」
- スマホでは HUD を画面下部に寄せ、ボタンは指で押せる大きさ（44 px 以上）にする
